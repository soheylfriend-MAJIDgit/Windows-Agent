## شناسنامه نسخه و کامیت در هدر

شماره‌ی نسخه از `version.txt` خوانده می‌شود؛ بنابراین فایل نسخه منبع یگانه است. `run.bat` پیش از باز کردن پنجره، شناسه‌ی کوتاه و تاریخ/ساعت آخرین کامیت Git را در `%LOCALAPPDATA%\\Windows-Agent\\build_stamp.json` می‌نویسد. هدر همیشه نسخه، شناسه‌ی کامیت و زمان جلالی تهران را نشان می‌دهد؛ شناسنامه در پوشه‌ی برنامه ذخیره نمی‌شود.

## به‌روزرسانی برنامه

برنامه **هیچ نسخه‌ای را خودش از گیت‌هاب نمی‌گیرد**. برای نسخه جدید، پروژه را با
GitHub Desktop به‌روزرسانی کن (Pull) و `run.bat` را دوباره اجرا کن.

## نصب وابستگی OCR محلی (اختیاری)

برای نصب PaddleOCR و مدل‌های CPU، روی `install_vision.bat` دوبار کلیک کن؛ فایل پیش از هر دانلود اجازه می‌گیرد و نصب را در یک محیط جداگانه‌ی `%LOCALAPPDATA%\\Windows-Agent\\vision` انجام می‌دهد. این نصب برای اجرای معمول برنامه اجباری نیست. اگر هنگام اجرای `run.bat` محیط OCR نصب نشده یا self-test آفلاین آن خراب باشد، برنامه پیشنهاد اجرای همین نصب‌کننده را می‌دهد؛ با انتخاب N برنامه بدون OCR باز می‌شود.

نصب PaddleOCR به Python 3.9 تا 3.11 نیاز دارد؛ BAT اول Python 3.11 را جست‌وجو می‌کند و خطاهای نصب را صریح نمایش می‌دهد. هیچ وابستگی OCR در Python اصلی برنامه نصب نمی‌شود.

## رابط کاربری (وب — pywebview)

پنجره‌ی برنامه یک صفحه‌ی وب است که داخل **WebView2** (موتور مرورگر Edge) نشان داده می‌شود:

- `assets/ui/index.html` + `style.css` + `app.js` = ظاهر برنامه
- `app.py` = منطق ویندوز؛ یک وب‌سرور کوچک روی `127.0.0.1` صفحه را سرو می‌کند
- ارتباط دو طرف با `window.pywebview.api` است (بدون اینترنت، همه‌چیز محلی)

یعنی گرافیک حالا با HTML/CSS است: کارت‌های گرد، سایه نرم، هاور، انیمیشن کلید، فونت وزیرمتن.

- **تم تاریک/روشن** با کلید ☀/🌙 در هدر (انتخاب ذخیره می‌شود)
- **افکت صوتی** برای هر مرحله:

| صدا | کجا |
|---|---|
| `click` | کلیک روی دکمه‌ها و تب‌ها |
| `toggle` | کلید حالت و صدا |
| `open` | باز کردن تصویر یا پوشه |
| `run` | شروع اجرای کد |
| `success` / `error` | پایان موفق یا خطا |
| `shutter` | گرفتن اسکرین‌شات |
| `tick` | سه ثانیه آخر شمارش معکوس |
| `notify` | نمایش پنجره تأیید |

- **حلقه‌ی شمارش معکوس** در کارت «حالت اجرا»: هر چند ثانیه که خودت بگذاری (پیش‌فرض ۱۰) یک دور، پیوسته و نرم پر می‌شود و سه ثانیه‌ی آخر هر ثانیه بوق می‌زند.
- فاصله‌ی دور خودکار همان‌جا در کارت «حالت اجرا» با یک کادر عددی عوض می‌شود (بین ۳ و ۶۰۰ ثانیه) و ذخیره می‌ماند.
- **تب «کتابخانه کدها»**: فهرست همه فایل‌های پایتون پوشه CODES با وضعیت اجرا و **دکمه پخش** برای اجرای مجدد هر کدام
- کلید قطع صدا 🔈/🔇 در هدر

> تصاویر نسخه ۱.۵ (pygame) در پوشه `docs/` مانده‌اند؛ تصاویر نسخه ۱.۶ بعد از تأیید ظاهر اضافه می‌شود.

## ربات تلگرام

تب **ربات تلگرام** چهار زیرتب دارد:

| زیرتب | کار |
|---|---|
| **تنظیمات** | توکن ربات (از @BotFather)، مقصد (`chat_id` گروه)، فاصله‌ی بین پیام‌ها، روشن/خاموش |
| **تست** | یک پیام واقعی به گروه می‌فرستد تا مطمئن شوی توکن و مقصد درست است |
| **صف پیام‌ها** | افزودن پیام (فوری یا زمان‌دار)، ارسال فوری، حذف، پاک‌کردن تاریخچه |
| **راهنمای ایجنت همکار** | کد آماده‌ی پایتون برای اینکه کدهای همکار پیام بفرستند |

**چطور کار می‌کند:** پیام‌ها در `%LOCALAPPDATA%\Windows-Agent\telegram_queue.json` صف می‌شوند و
یک کارگر در پس‌زمینه هر پیام را با فاصله‌ی امن (پیش‌فرض ۳ ثانیه) می‌فرستد. اگر تلگرام بگوید
«زیاد فرستادی»، خودش `retry_after` را می‌خواند و صبر می‌کند. پیام ناموفق با دلیلش در صف می‌ماند.

**ایجنت همکار** با یک آدرس محلی پیام می‌گذارد؛ آدرس و کلید در فایل
`%LOCALAPPDATA%\Windows-Agent\bot_api.json` نوشته می‌شود و کد او همان را می‌خواند:

```python
import json, os, urllib.request

CFG = os.path.join(os.environ["LOCALAPPDATA"], "Windows-Agent", "bot_api.json")

def tell(text, delay=0, chat_id=None):
    with open(CFG, encoding="utf-8") as fh:
        cfg = json.load(fh)
    body = json.dumps({"text": text, "delay": delay, "chat_id": chat_id}).encode("utf-8")
    req = urllib.request.Request(
        cfg["send"], data=body, method="POST",
        headers={"Content-Type": "application/json", "X-Agent-Token": cfg["token"]},
    )
    with urllib.request.urlopen(req, timeout=10) as resp:
        return json.loads(resp.read().decode("utf-8"))

tell("سلام! این پیام از کد ایجنت همکار است.")      # همین حالا
tell("یادآوری — ۱۰ دقیقه بعد", delay=600)            # در صف
```

- جواب موفق: `{"ok": true, "id": "...", "queued": true}`
- جواب خطا: `{"ok": false, "error": "..."}`
- وضعیت صف: همان آدرس با مسیر `/bot/state` و همان کلید
- سرور فقط روی `127.0.0.1` گوش می‌دهد و بدون کلید محلی جواب نمی‌دهد.

## هیچ فایلی کنار برنامه نوشته نمی‌شود

پوشه برنامه فقط `app.py` و `run.bat` است. فایل‌های وضعیت در این مسیر هستند:

```
%LOCALAPPDATA%\Windows-Agent\
├── settings.json      ← حالت دستی/خودکار و مخزن همکار
├── codes_state.json   ← کدام فایل‌ها اجرا شده‌اند
├── build_stamp.json   ← شناسه نسخه
├── webview\           ← حافظه‌ی داخلی پنجره‌ی وب (تم و تنظیمات رابط)
├── telegram_queue.json← صف پیام‌های ربات تلگرام
├── bot_api.json       ← آدرس و کلید محلی ربات (برای کدهای ایجنت همکار)
└── backups\           ← پشتیبان app.py قبل از هر بروزرسانی
```

و هر خطایی — خطای دریافت مخزن، خطای اجرای کد، خطای بالا نیامدن برنامه —
در `logs\errors\errors_<تاریخ جلالی>.txt` گوگل درایو ثبت می‌شود.

## چطور کار می‌کند

1. برنامه موقع باز شدن، پوشه `Desktop\CODES` را چک می‌کند و اگر نبود می‌سازد.
2. مخزن ایجنت همکار بررسی می‌شود (مخزن و شاخه داخل خود برنامه قابل تنظیم است).
3. هر فایل `.py` جدید در پوشه `CODES` ذخیره می‌شود.
4. همان فایل اجرا می‌شود و نتیجه در `logs` گوگل درایو نوشته می‌شود.

## یک کلید: دستی یا خودکار

| حالت | رفتار |
|---|---|
| **🔒 دستی** (پیش‌فرض) | هیچ کاری بدون اجازه تو انجام نمی‌شود؛ برای هر فایل و هر اجرا از تو می‌پرسد |
| **⚡ خودکار** | بررسی مخزن، دانلود و اجرا هر N ثانیه (پیش‌فرض ۱۰، از خود صفحه قابل تغییر) بدون پرسیدن انجام می‌شود |

انتخابت در `settings.json` ذخیره می‌شود.

## اجرا

1. `run.bat` را دوبار کلیک کن. اگر `pywebview` یا `Pillow` نصب نباشد، **خودش نصب می‌کند** و بعد برنامه را باز می‌کند.
   روی ویندوز به **WebView2 Runtime** نیاز است؛ ویندوز ۱۱ و ویندوز ۱۰ به‌روز آن را دارند.
   اگر نبود، یک‌بار از [این آدرس](https://developer.microsoft.com/microsoft-edge/webview2/) نصبش کن.
2. در تب **ایجنت همکار**، مالک / مخزن / شاخه را وارد کن و «💾 ذخیره» بزن.
3. دکمه «📥 بررسی مخزن همکار» → فایل‌ها در `CODES` ذخیره می‌شوند.
4. دکمه «▶️ اجرای کدهای جدید» → اجرا و نتیجه در `logs`.
